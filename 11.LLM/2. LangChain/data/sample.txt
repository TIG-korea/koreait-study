Redis는 인메모리 기반 NoSQL 데이터베이스이다.

Redis는 메모리에 데이터를 저장하기 때문에 매우 빠른 읽기 및 쓰기 성능을 제공한다.
주로 캐시 서버, 세션 저장소, 실시간 랭킹 시스템 등에 사용된다.

Redis는 Key-Value 구조를 기반으로 데이터를 저장한다.
문자열(String), 리스트(List), 셋(Set), 정렬된 셋(Sorted Set), 해시(Hash) 등의 자료구조를 지원한다.

Redis는 TTL(Time To Live) 기능을 제공한다.
TTL은 특정 Key에 만료 시간을 설정하는 기능이다.
설정된 시간이 지나면 해당 Key는 자동으로 삭제된다.

Redis TTL은 로그인 세션 관리, 인증 코드 저장, 임시 캐시 데이터 처리 등에 자주 사용된다.

Redis는 Pub/Sub 기능도 제공한다.
Pub/Sub은 Publisher와 Subscriber 기반 메시징 기능이다.
실시간 채팅 시스템이나 알림 시스템 구현에 사용된다.

Redis는 영속성 기능도 제공한다.
RDB 방식과 AOF(Append Only File) 방식을 지원한다.
RDB는 특정 시점의 스냅샷을 저장하고,
AOF는 모든 쓰기 명령을 로그 형태로 저장한다.

Redis는 싱글 스레드 기반으로 동작한다.
하지만 메모리 기반 구조이기 때문에 매우 높은 성능을 제공한다.

Kafka는 대용량 실시간 메시지 처리 시스템이다.
LinkedIn에서 개발되었으며 현재는 Apache 오픈소스 프로젝트이다.

Kafka는 이벤트 스트리밍 플랫폼으로 사용된다.
대량의 데이터를 안정적으로 수집하고 전달할 수 있다.

Kafka는 Producer와 Consumer 구조를 사용한다.
Producer는 메시지를 발행하고,
Consumer는 메시지를 읽는다.

Kafka는 Topic 단위로 데이터를 관리한다.
Topic은 메시지를 저장하는 논리적인 채널이다.

Kafka Topic은 여러 개의 Partition으로 구성될 수 있다.
Partition을 통해 메시지를 병렬 처리할 수 있다.

Kafka Consumer Group은 여러 Consumer가 메시지를 분산 처리할 수 있도록 지원한다.
같은 Group 내부에서는 하나의 Partition을 하나의 Consumer만 읽는다.

Kafka는 Offset 기반으로 메시지를 관리한다.
Consumer는 자신이 어디까지 읽었는지 Offset으로 기록한다.

Kafka는 높은 처리량과 확장성을 제공한다.
실시간 로그 수집, 이벤트 처리, 데이터 파이프라인 구축 등에 자주 사용된다.

Kafka는 메시지를 즉시 삭제하지 않는다.
설정된 Retention 기간 동안 데이터를 보관한다.

FastAPI는 Python 기반 비동기 웹 프레임워크이다.

FastAPI는 Python Type Hint를 적극적으로 활용한다.
이를 기반으로 자동 데이터 검증 기능을 제공한다.

FastAPI는 Pydantic 기반 데이터 검증 기능을 제공한다.
Pydantic은 요청 데이터의 타입과 구조를 검증한다.

FastAPI는 Swagger UI 문서를 자동 생성할 수 있다.
브라우저에서 API 테스트도 가능하다.

FastAPI는 비동기(async/await) 기반 처리를 지원한다.
고성능 네트워크 애플리케이션 구현에 적합하다.

FastAPI는 Dependency Injection 기능을 제공한다.
공통 로직을 재사용하기 쉽게 만들어준다.

FastAPI는 REST API 서버 개발에 자주 사용된다.
AI 서버, 마이크로서비스, 비동기 API 서버 구현 등에 활용된다.

RAG(Retrieval-Augmented Generation)는 검색 기반 생성 기술이다.

RAG는 외부 문서를 검색한 뒤,
검색된 내용을 기반으로 LLM이 답변을 생성하는 구조이다.

RAG는 일반적인 LLM의 환각(Hallucination) 문제를 줄이는 데 도움을 준다.

RAG 시스템은 일반적으로 다음 단계로 구성된다.
문서 로딩
문서 분할
임베딩 생성
벡터 저장
유사도 검색
LLM 답변 생성

임베딩(Embedding)은 텍스트를 벡터 형태로 변환하는 과정이다.

FAISS는 벡터 유사도 검색을 위한 라이브러리이다.
Facebook AI Research에서 개발하였다.

Retriever는 사용자의 질문과 유사한 문서를 검색하는 역할을 수행한다.

LangChain은 LLM 애플리케이션 개발을 위한 프레임워크이다.

LangChain은 PromptTemplate, Runnable, Chain, Retriever 등의 기능을 제공한다.

RunnablePassthrough는 입력 데이터를 그대로 다음 단계로 전달하는 Runnable이다.

RunnableLambda는 사용자 정의 함수를 Runnable 형태로 연결할 수 있게 해준다.

StrOutputParser는 LLM의 응답을 문자열 형태로 변환한다.

Conversation Memory는 이전 대화를 저장하는 기능이다.
